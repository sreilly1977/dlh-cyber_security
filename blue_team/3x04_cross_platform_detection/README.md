Platform note: The COD platform used for this module does not provide live Wazuh dashboard access, Docker socket mount, or browser connectivity to port 5601. This project uses the Wazuh export mode: instead of querying a live dashboard, you read local JSON files that capture what the Wazuh interface would show. The investigation workflow, the finding schema, and the comparison deliverables are identical to the live-dashboard design. The data is identical. What differs is the access method.

Same evidence. Same scenarios. Same ATT&CK techniques. Two completely different interaction models — one live, one export-based — but the analytical work is the same.

At the end of the week you will have investigated three scenarios through two interfaces, translated Sigma rules into native Wazuh XML rules, built a side-by-side query language comparison that covers jq, Sigma, KQL, and Lucene, written a tool-agnostic investigation playbook, and delivered a bounded vendor evaluation brief that James Chen can put in front of the MedDefense board.

## Why this matters

The SOC industry does not hire SIEM operators. It hires security analysts who can operate any SIEM. Every serious SOC changes its primary platform every three to five years. License costs shift, acquisitions happen, cloud migrations force a platform change, open source licensing terms get rewritten. The analyst who only knows one interface becomes a liability during every transition. The analyst who can look at any query language and decompose it into filters, aggregations, and time windows gets promoted through the transition. That is the difference between a dashboard user and a detection analyst and it is the gap this project exists to close.

There is a second reason that matters more this month. MedDefense is in the middle of a platform evaluation. The board has approved budget for the infrastructure review. Compliance wants evidence that the SOC made a vendor-informed decision, not that they just kept what was convenient. James Chen does not need a spreadsheet of features. He needs an analyst who investigated real incidents on both interfaces and who can defend a recommendation with evidence. That analyst is you this week. Every finding you file, every rule you translate, every click you count, and every command you log becomes part of the brief that ends up in front of Dr. Morales.

# [10. Sigma to Wazuh Rule Translation](https://github.com/sreilly1977/dlh-cyber_security/tree/main/blue_team/3x04_cross_platform_detection/10-rule_translation.sh)
### advanced

## Goal: 

Translate three Sigma rules from the 3x02 catalog into native Wazuh XML rules, validate them with xmllint, and produce a translation report.

## Context: 

Sigma is vendor-neutral on purpose, but the day a detection rule ships into a specific SIEM it has to speak that SIEM's native language. Wazuh uses an XML rule format with <if_sid>, <frequency>, <timeframe>, and <same_source_ip/>. The translation is validated with xmllint (not wazuh-logtest, which is not available outside the container) to confirm the XML is well-formed. A match count verification compares how many events each Sigma rule matches against the enriched events with your 3x02 runner, then verifies the Wazuh XML would match the same events based on the field logic.

## Instructions: 

Write 10-rule_translation.sh that produces, validates, and reports three translations. The script must:

    Translate $CATALOG_DIR/rules/sigma/001_ssh_brute_force.yml to rules/wazuh/001_ssh_brute_force.xml — use Wazuh frequency syntax: <if_sid>5710</if_sid>, <frequency>5</frequency>, <timeframe>120</timeframe>, <same_source_ip/>
    Translate $CATALOG_DIR/rules/sigma/003_interpreter_abuse.yml to rules/wazuh/003_interpreter_abuse.xml — single-event rule with <field name="win.eventdata.image"> matches
    Translate $CATALOG_DIR/rules/sigma/010_credential_theft_chain.yml (or 009_credential_theft_chain.yml if numbered differently) to rules/wazuh/010_credential_theft_chain.xml
    Validate every produced XML file with xmllint --noout file.xml and record exit code
    Run the original Sigma rule against a scoped event set using your 3x02 runner and count matches
    Emit rules/wazuh/translation_report.json with: input Sigma rule path, output XML path, xmllint status, sigma match count, and translation status

**Expected Output:**
