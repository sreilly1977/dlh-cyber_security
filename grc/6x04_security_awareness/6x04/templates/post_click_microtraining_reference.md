# Post-Click Microtraining Reference

Use this file when designing `post_click_intervention.md`.

## Required Structure

Each landing page variant should contain:

1. "This was a simulation"
2. "Why it was convincing"
3. "What to notice next time"
4. "What a real attacker could gain"
5. "What to do now"
6. Report button reminder

## Non-Shaming Language Examples

Use:

- "This message was designed to feel realistic."
- "The safest next step is verification, not speed."
- "Reporting after a click still helps the security team."
- "You are not in trouble; this is a training moment."

Avoid:

- "You failed."
- "You were fooled."
- "This was obvious."
- "You should have known."

## Four-Part Microtraining Model

### What You Saw

Use exact cues from the template.

### What a Real Attacker Gains

Tie to operational impact: EHR access, payroll data, payment approval, remote access.

### What To Do Next Time

Give three role-specific actions.

### How To Report

Use Outlook phishing report button, ext. 4-SECURITY or security@meddefense.org.

## Positive Reinforcement

For correct reports, respond within 60 seconds with:

- confirmation
- specific cue they noticed
- thank-you message
- what happens next
