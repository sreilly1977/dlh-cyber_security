# Reporting and Triage Model

## Reporting Channels

| Channel | Intended Use |
|---|---|
| Anonymous web form | Employee concern without naming self |
| security@meddefense.org | Non-urgent security concern |
| ext. 4-SECURITY | Immediate security concern |
| HR hotline | Workplace concern with personnel sensitivity |
| Manager escalation | Operational context concern |

## What To Report

Report observable facts:

- account used outside expected purpose
- unusual request for access
- repeated attempt to bypass approval
- suspicious vendor pressure
- data access inconsistent with role
- employee asking for credentials or MFA codes
- remote support request without ticket

Do not report speculation about personality, protected characteristics or workplace disagreements.

## Triage Steps

1. Intake records reporter, date, channel, and observable facts.
2. Security triage determines whether technical evidence exists.
3. HR is included only if the concern involves employee conduct, manager action or coaching.
4. Legal is included if privacy, employment or regulatory exposure exists.
5. Investigation proceeds with minimum necessary disclosure.
6. Reporter receives acknowledgment where appropriate.

## Escalation Threshold

Escalate to HR and Legal when:

- technical evidence supports policy violation
- repeated pattern exists after coaching
- privileged access misuse is suspected
- patient record misuse is suspected
- retaliation concern exists
- manager is involved in the report subject

## Non-Retaliation Statement

MedDefense prohibits retaliation against any workforce member who raises a good-faith security or safety concern. Retaliation concerns are reviewed by HR and Legal.
